# PDP-11: Pac-Man — план

Итог планирующей сессии 2026-07-18. Старт реализации — следующая сессия.
Фаза BASIC ([basic-plan.md](basic-plan.md)) не отменена — отложена; Pac-Man вперёд.

Цель: третья игра на закладке рядом с Arkanoid/Tetris. Из трёх — самая большая:
пять спрайтов в четырёх направлениях, лабиринт с топологией, четыре призрака с
характерами. Машина справляется с запасом, вопрос только в объёме ассемблера.

---

## Принятые решения

### Геометрия
- **Тайл 16×16 px.** Поле 28×31 тайлов = 448×496, в экране 512×512 с полями
  по 32 px. 16 px = **ровно 2 байта** фреймбуфера — тайловая графика байт-чистая.
- **Скорость 2 px/кадр** (оригинал ~1.26 px/кадр при вдвое меньших тайлах — наш
  темп почти точно его). Следствие: x всегда чётный → у спрайтов **4 фазы сдвига**
  вместо 8, вдвое меньше прешифтованных масок.
- **Спрайты 14×14**, отцентрованы в 16-px коридоре — стен не задевают.
  Восстановление фона под спрайтом = перерисовка точек максимум в 4 тайлах
  по карте (не по пикселям).
- **Туннель**: выход в 32-px поле, перенос на другой край; призраки в туннеле
  замедляются (пропуск каждого второго кадра).

### Лабиринт
- **Своя планировка**, не намковская. Симметричная, в том же духе: дом призраков
  в центре, туннель, энерджайзеры по углам.
- **Карта — ASCII-артом в исходнике**: 31 строка `.ASCII /...`; `#` стена,
  `.` точка, `o` энерджайзер, `-` дверь дома, пробел — пустой коридор.
  При старте программа разбирает арт в тайловую карту (28×31 = 868 байт)
  и рисует поле. Читаемо и правится прямо в редакторе на сайте.
- **Коллизии и повороты — по карте тайлов**, не по пикселям (в отличие от
  Арканоида): «можно ли ехать туда» = один CMPB.
- **Стены — контурные линии** по границе стена/коридор, автотайлинг по маске
  соседей (вариант «б»; дизеринг-заливку отвергли). Весь автотайлинг — boot-time,
  кадровый бюджет не трогает.

  > **Как вышло на деле (2026-07-19, 233ff6c): автотайлинг отвергнут.** Он
  > оставлял незакрытыми стыки в вогнутых углах (20 дыр) — вывод шёл в сторону,
  > где случай на каждую конфигурацию соседей. Заменено: ассемблер знает CP437,
  > лабиринт **нарисован рамками** прямо в `.ASCII` (один символ = клетка,
  > `═` — ворота дома), глифы генерятся из маски связей и стыкуются по
  > построению, а твёрдость читается обратно с картинки — один бит на символ.
  > Пункты про `#`/`-` и «карта → автотайлинг» выше устарели.
- Точка 4×4 в центре тайла, энерджайзер 8×8, мигает по счётчику кадров.

### Призраки — полный AI четырёх личностей
- Ядро оригинального алгоритма дёшево: на перекрёстке призрак выбирает
  направление, **минимизирующее квадрат расстояния до тайла-цели**;
  разворачиваться нельзя. MUL нет, но расстояния ≤ 31 тайла →
  **таблица квадратов на 32 слова** вместо умножения.
- Личности = разные цели:
  - **Blinky** — тайл Пакмана;
  - **Pinky** — 4 тайла впереди Пакмана, **с воспроизведением оригинального
    бага**: при взгляде вверх цель смещается ещё и на 4 влево (переполнение
    в коде 1980 года) — исторический артефакт, задокументировать комментарием;
  - **Inky** — вектор от Blinky к точке «2 впереди Пакмана», удвоенный (сдвиг);
  - **Clyde** — Пакман, если дальше 8 тайлов; иначе свой угол (scatter-цель).
- **Scatter/chase** чередуются по таблице интервалов на счётчике кадров.
- **Frightened** по энерджайзеру: все разворачиваются, замедляются, мигают
  под конец; выбор направления — псевдослучайный (LFSR в одно слово);
  поедание 200-400-800-1600, глаза бегут в дом.
- **Дом призраков — упрощение** (единственное): выход по таймерам со
  стаггером, без оригинальных пер-призрачных счётчиков точек.

### Остальное
- Счёт/жизни: шрифт 5×7 и схема из Арканоида, переиспользовать.
- Звук: waka-waka на поедании точки (пачки тоглов спикера, движок как в
  тетрисной музыке), джингл смерти, warble в frightened. Сирена — опция на
  полировку: она звучит постоянно и ест кадровый бюджет, решить по факту.
- Смерть: анимация схлопывания, −1 жизнь, рестарт позиций; 0 жизней → game
  over → HALT (как в Арканоиде). Съедены все точки → следующий уровень
  (быстрее призраки, короче frightened).
- **Кадровый бюджет**: 5 спрайтов с прешифтованными масками + восстановление
  фона ≈ 3–4К тактов, AI только на перекрёстках, точки — O(1) по карте.
  В 16667 тактов — с большим запасом.
- **Память**: код + карта (868) + тайловая карта (868) + таблица квадратов (64)
  + спрайты с прешифтом (~2К) — свободно в дырке до 060000.

### Хост (единственное изменение «железа»)
- **Джойстику нужен UP**: новый бит `JOY_UP = 020`. ArrowUp перестаёт быть
  синонимом FIRE (Space остаётся FIRE — в Pac-Man это «старт/пауза»).
  В тач-контролы добавляется ▲ (крестовина). Арканоид/Тетрис не трогаются:
  их биты на месте.
- Закладка в App: **Pac-Man**.

### Тесты (headless, в духе имеющихся)
- Карта разобрана и нарисована: счётчик точек сходится с числом `.`+`o` в арте.
- Скриптованные повороты: Пакман ест точки, счёт растёт, waka-события в логе
  спикера.
- Призрак выходит из дома и на перекрёстке выбирает сторону по своей цели.
- Энерджайзер: разворот призраков, поедание, 200-400-…, глаза в дом.
- Столкновение → жизнь −1; 0 жизней → HALT.
- Туннель: перенос через край для Пакмана и призрака.

## Порядок сборки и оценка — одна сессия

Ориентир — сессия 2026-06-11: эмулятор + ассемблер + оболочка + Арканоид за один
день, с нуля. Pac-Man пишется на готовой машине с отлаженным тулчейном и тестовой
обвязкой; ассемблера будет ~2× Арканоида (~600–700 строк), но инфраструктурной
работы — один бит джойстика. Этапы — просто порядок внутри сессии:

- **P0** — хост (JOY_UP + ▲ + закладка), карта ASCII → тайлы, автотайлинг стен,
  точки, Пакман ездит/ест/анимация рта, счёт, туннель.
- **P1** — призраки: таблица квадратов, движение по перекрёсткам, четыре цели,
  scatter/chase, frightened, дом, смерть/уровни, звук, полировка.
