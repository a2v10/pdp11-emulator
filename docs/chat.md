**Memory + Bus.** Память — `Uint16Array(32768)` (64KB, адресация байтовая, как в настоящей PDP-11 — это важно для `MOVB` и little-endian порядка байт). Bus — тонкий слой; всё ниже 0o160000 идёт в RAM напрямую, страница ввода-вывода диспетчеризуется на устройства. Фреймбуфер при этом — просто кусок обычной RAM, его не нужно перехватывать: React сам читает его при отрисовке.

**CPU.** R0–R7 (R6=SP, R7=PC), PSW с N/Z/V/C и приоритетом. `step()` исполняет одну инструкцию и возвращает условные такты. Набор инструкций: базовый комплект плюс, я бы сразу добавил, EIS (MUL/DIV/ASH) — без умножения вычислять адрес пикселя по X,Y муторно, хотя и можно сдвигами. Без MMU и FPU. Самая «дорогая» часть — режимы адресации: их 8, и они общие для всех инструкций.

**Прерывания.** В настоящей PDP-11 они есть, и я бы сделал аутентично: консольный ввод DL11 (статус-регистр **177560**, буфер **177562**, вектор **060** — ровно как в железе) и line clock KW11 (регистр **177546**, вектор **100**, тикает 60 Гц). Это решает проблему тайминга игры — Арканоид синхронизируется по этому прерыванию, никаких busy-loop'ов на угадывание скорости.

Одна неаутентичная уступка, которую советую: терминальный ввод даёт *символы*, а для игры нужно состояние *удерживаемых* клавиш. Предлагаю дополнительный регистр в I/O-странице — битовая маска «влево/вправо/space».

**Дисплей.** 256×256 @ 1bpp = ровно 8KB, красивое число: 16 слов на строку, адрес пикселя считается сдвигами.

**Ассемблер.** Классический двухпроходный: подмножество MACRO-11, восьмеричные литералы по умолчанию (это PDP-11, всё в octal!). На выходе — бинарный образ + таблица символов.

Пара вопросов на подумать (не блокеры, у меня есть дефолты): чистый JS или TypeScript — для CPU с его таблицами типы сильно помогают; и octal-литералы `0o...` в коде эмулятора я бы использовал везде — PDP-11 в шестнадцатеричном виде нечитаема.

**Память.** Делаем хитрее, чем просто Uint8Array: один `ArrayBuffer(65536)` и два view на него — `Uint8Array` для байтовых операций и `Uint16Array` для словных. Little-endian порядок совпадает с PDP-11 автоматически (все реальные JS-движки крутятся на little-endian железе). Бонус аутентичности: словный доступ по нечётному адресу — трап через вектор 4, как в железе.

**Режимы адресации.** Согласен, неудачно выразился — «дорого» не в смысле вентилей или тактов, а в смысле поверхности для ошибок: автоинкремент на 1 для байтовых операций, но на 2 для R6/R7; mode 2 c R7 — это immediate; mode 6/7 дочитывают слово из потока инструкций со сдвигом PC. В железе это и правда горстка вентилей, в эмуляторе — одна аккуратная функция, просто на неё нужны тесты. Вопрос закрыт.

**Умножение.** Да, с 512×512 всё складывается само: строка = 512 px = 64 байта, адрес пикселя = `база + (y << 6) + (x >> 3)`, бит — `x & 7`. Чистые сдвиги, EIS выкидываем, остаётся базовый набор инструкций. Красиво.

**Карта памяти** (512×512 = 32KB фреймбуфер, пришлось подвинуть):

| Octal | Размер | Что |
|---|---|---|
| 000000–000377 | 256 B | векторы прерываний/трапов |
| 000400–057777 | ~24 KB | код, данные, стек |
| 060000–157777 | 32 KB | фреймбуфер 512×512, 1bpp, 64 байта/строка |
| 160000–177777 | 8 KB | страница ввода-вывода |

24KB под код — для Арканоида на ассемблере это космос.

**Джойстик.** Одно слово в I/O-странице, скажем **177570**: битовая маска текущего состояния — bit 0 влево, bit 1 вправо, bit 2 fire/start. React держит keydown/keyup и просто выставляет биты. Как декодировала настоящая PDP-11: поле IR нарезано на восьмеричные цифры, и комбинационная логика смотрит на них **иерархически**. Формат инструкций спроектирован под это — он красиво раскладывается по октальным разрядам:

```
биты 14-12 (старшая октальная цифра без byte-бита):
  1..6 → двухоперандные (MOV/CMP/BIT/BIC/BIS/ADD), бит 15 = byte/word (ADD↔SUB)
  7    → группа 07: следующая цифра: 0-3 EIS (у нас нет), 4 XOR, 7 SOB
  0    → разбираем следующую цифру:
           004x → JSR;  005x, 006x → однооперандные
           0004..0034 и 1000..1034 → ветвления
           0000 → хвост: HALT/WAIT/RTI/..., 0001 JMP, 0002 RTS/CC, 0003 SWAB
```

**Предложение:** декодер — каскад вложенных `switch` по этим полям, прямой аналог той самой горстки вентилей. Читается как принципиальная схема, один в один ложится на страницу из Processor Handbook, и его же потом можно подсветить на схеме процессора («смотри, эти три бита выбрали группу, эти — операцию»). Бонус: V8 компилирует плотные switch по маленьким числам в jump table, так что по скорости это не хуже моей таблицы.
