# PDP-11: текстовый терминал + BASIC — план

Итог проектной сессии (2026-06-16). Старт реализации — 2026-06-17.

Цель фазы: превратить эмулятор из «машины, которая крутит игру» в **домашний/школьный
компьютер** — текстовый терминал и BASIC, в который грузишься с порога. BASIC — это
просто ещё одна программа на ассемблере, новая закладка рядом с Arkanoid/Tetris;
«Assemble & Run» зажигает курсор и входит в REPL. Эмулятор не знает, что крутит
BASIC, — как и раньше не знал, что крутит Арканоид.

---

## Идентичность машины

Мы строим не миникомпьютер DEC, а **домашний микро линии БК-0010 / УКНЦ** (процессоры
К1801, PDP-11-совместимые; экран — память; загрузка в интерпретатор). Один принятый
анахронизм — 32-КБ фреймбуфер: в настоящей DEC-овской PDP экран в core никто не держал
(терминал на последовательной линии), а БК на меньшем экране тратил 16 КБ. Для BASIC
маргинальная стоимость памяти **ноль** — используем уже существующий фреймбуфер.

Сквозная линия: **стек-машина + плавающая точка + DEC-формат + рекурсивный спуск ≈
ФОКАЛ, переписанный на '11**. ФОКАЛ — плавающий стек-калькулятор, DEC-овский язык,
сидевший в ПЗУ БК. То есть мы возрождаем DEC-овский язык на его же архитектуре.

## Принятые решения

### Дисплей / терминал
- **Знакоместо 8×16, экран 64×32**, на весь фреймбуфер 512×512.
  64 колонки × 8 px = 64 байта = ровно одна строка фреймбуфера (`FB_BYTES_PER_ROW`).
  Колонка `cx` → байт `cx`, без полей и центрирования. 32 строки × 16 = 512.
- **Знакогенератор — байт-чистый**: 8 px = 1 байт → один `MOVB` на строку глифа,
  **ноль масок**. Адрес базы ячейки `(cx,cy)` = `FB + (cy<<10) + cx`, каждая из 16
  строк глифа добавляет 64 (`<<6`). Чистые сдвиги, без умножения.
- **Шрифт 8×16**, 96 глифов (ASCII 0x20–0x7F) = 1536 байт как `.BYTE`. Взять готовый
  известный ROM-шрифт 8×16 и переложить в восьмеричное. text RAM 64×32 = 2048 байт.
- **Грязный рендер, не полный перерисов**: запись в text RAM → отрисовали ту ячейку
  (8×2 = 16 `MOVB`). Полный перерисов (8000 пересылок) > бюджета кадра 1 МГц — не делаем.
- **Курсор** мигает по тику KW11 (60 Гц), переключаем глиф каждые ~30 тиков.

### Скролл — кольцевой буфер регистром, обмотка в Canvas
- Модель БК-0010: **регистр смещения 0177664** (биты 0–7 — стартовая строка; изменение
  на 1 = сдвиг на 1 растровую строку; обмотка). У нас 512 строк → поле смещения **9 бит**.
- Машина при скролле: **бампает регистр на 16** (одно знакоместо = 16 строк) + чистит
  одну въезжающую строку → **O(1)**, в памяти ничего не двигается.
- `Screen` (он и так читает фреймбуфер бесплатно) рисует со сдвигом **mod 512**.
- Оговорка: фреймбуфер общий с играми → смещение по умолчанию 0, обмотка только когда
  регистр ненулевой / только для текстовой области.

### Ввод — DL11, чистый DEC
- Приёмник: **RCSR 0177560** (бит 7 = done, бит 6 = IE), **RBUF 0177562** (символ),
  **вектор 060**. Передатчик не нужен — вывод идёт в экран через знакогенератор.
- Хост роутит печатные клавиши + Enter + Backspace в FIFO устройства (по шаблону
  джойстика). Джойстик остаётся для игр — сосуществуют на шине.
- Фокус: пока печатаешь в BASIC, фокус не должен быть на editor-TEXTAREA, иначе
  нажатия уедут туда.

### Без монитора
- **Никакого резидентного монитора и EMT-слоя.** Консольный драйвер (PUTCHAR/GETLINE/
  курсор/скролл), плавающая математика, знакогенератор, интерпретатор — всё внутри
  `basic.s`, как в `arkanoid.s`/`tetris.s`. `load()` уже делает «BASIC — это просто
  программа»: `PC = entry`, `SP = 060000`, запуск.

### Парсер и вычислитель (ядро)
- **Рекурсивный спуск, приоритеты — в структуре грамматики** (НЕ таблица, НЕ
  shunting-yard/RPN). Грамматика:
  ```
  expr    := term   (('+'|'-') term)*      ; левая, низший приоритет
  term    := factor (('*'|'/') factor)*    ; левая
  factor  := unary  ('^' factor)?          ; правая (если ^ берём)
  unary   := '-' unary | primary           ; унарный минус — просто продукция
  primary := NUMBER | VAR | VAR '(' expr ')' | FN '(' expr ')' | '(' expr ')'
  ```
- **Стратегия исполнения: AST → байткод стековой машины → исполнять** (линия
  p-code / UCSD Pascal, а НЕ on-the-fly-обход домашних BASIC'ов). Рекурсивный спуск —
  это **фронт компилятора**: `expr/term/factor` не считают в R0, а **эмитят опкоды**
  (`PUSHC/PUSHV/ADD/SUB/MUL/DIV/NEG/CALL_FN`). Крошечная VM = цикл диспетча, **стек
  операндов на R6** (pushdown в духе ФОКАЛ, но даром: у '11 есть SP/JSR/RTS).
- **Зачем байткод, хотя скорость не нужна:** (1) **обучение** — две вложенные
  прошагиваемые машины: `2+3*4` → `PUSHC 2·PUSHC 3·PUSHC 4·MUL·ADD`, видно стек
  (это и есть «схема с подсветкой потоков» на двух уровнях; у обхода дерева промежутка
  нет); (2) синтаксис ловится на компиляции/`RUN`, не на N-й итерации `FOR`;
  (3) компилятор и VM тестируются порознь. Дельта над on-the-fly мала — спуск уже есть,
  меняем «вычислить» на «эмитнуть».
- **Плавающая точка: DEC F-format, 32 бита** (знак / 8-бит порядок excess-128 /
  24-бит мантисса со скрытым битом). Софт. Мантисса mul/div = shift-add + бухгалтерия
  порядка + нормализация. overflow → `?OV ERROR`, underflow → 0.
- Спуск делает correct-by-construction: приоритеты, унарный минус, скобки,
  «операнд — сам выражение» (функции, `A(I)`). Вычислитель — территория first-try.
  Единственный угол под тест-молоток — **печать float в десятичную строку**.

### Структура интерпретатора (S1–S4)
- **Токенизатор**: ключевые слова → однобайтовый токен (старший бит). Программа —
  отсортированные строки `[line#][len][токены]`. **Защищать строковые литералы** от
  токенизации (`PRINT "GOTO"`).
- **REPL/редактор**: строка с номером → вставка/замена/удаление; без номера → direct
  mode. `LIST/RUN/NEW`.
- **Операторы**: `LET, PRINT, INPUT, IF/THEN, GOTO, GOSUB/RETURN, FOR/NEXT, DIM,
  REM, PEEK/POKE, BEEP` (бипер 0177544 уже есть).
- **Таблицы**: текст программы, переменные, массивы, строковое пространство, стеки
  GOSUB/FOR. SP с 060000.
- **Бюджет памяти**: шрифт 1536 + text RAM 2048 + интерпретатор ~4–8 КБ → ~14 КБ под
  программу пользователя и переменные в 24-КБ дырке. Щедро.

### Тулчейн
- **Добавить минимальный `.MACRO`/`.ENDM` в ассемблер.** BASIC — первая программа,
  где отсутствие макросов кусает (таблицы диспетчеризации, данные глифов). Сделать
  заранее. Сейчас ассемблер умеет: `.WORD .BYTE .ASCII .ASCIZ .BLKW .BLKB .EVEN .END`
  — ни макросов, ни условной сборки.

### Тестирование
- Headless по всему: скормить поток нажатий, прогнать N кадров, проверить text RAM /
  вывод. В духе существующих ~109 тестов. Детерминизм + snapshot/rewind → любой баг
  воспроизводится бит-в-бит.

## Открытые решения (спецификация — за Алексом, «остальное скажу сразу»)

1. **`^`** (степень): берём или выкидываем? (для float ок, нужна подпрограмма power).
2. **true = -1 (MS) или 1 (Woz)?**
3. **Грамматика приоритетов** — подтвердить лесенку: `(...)`/функции → унарный `-` →
   `^` → `* /` → `+ -` → сравнения `= <> < > <= >=` → `NOT` → `AND` → `OR`; всё в
   одном спуске, булево как 0/-1.
4. **Печать float**: число значащих цифр, порог E-нотации, округление последней цифры.
5. **FOR/NEXT семантика**: `FOR I=1 TO 0` — тело один раз или ноль? `STEP 0`,
   отрицательный шаг. (тест на NEXT vs тест сверху).
6. **Имена переменных**: `A`–`Z`, `A0`–`Z9`? Строковые `A$`? Массивы/`DIM`.
7. **Набор встроенных функций**: `ABS, INT, SGN, RND, PEEK, ...`.
8. **Адрес регистра скролла**: берём БК-овский 0177664 (по умолчанию — да) или свой.
9. **Байткод и `LIST`**: двойное хранение (токенизированный исходник для листинга +
   байткод для исполнения) или ленивая компиляция по строке с кэшем?

## Порядок сборки и оценка

Оценка после упрощения вычислителя — **~3–4 плотных сессии** (сессия ≈ интенсивный
день, как исходная сборка машины). Отдельная «сессия отладки краевых эффектов» НЕ нужна
— рекурсивный спуск убрал её причину; молотить тестами одно место — float→string.

- **S0** — «терминал, на котором можно печатать»: DL11 + регистр скролла + обмотка в
  Canvas + знакогенератор 8×16 + консольный драйвер + шрифт + тесты. ~1 сессия.
- **`.MACRO`** в ассемблер — ~0,5 сессии, до/вокруг S1.
- **S1** — REPL + рекурсивный спуск с плавающим вычислением + `PRINT` → `PRINT 2+3`. ~1.
- **S2** — токенизация + хранение программы + `LIST/RUN/NEW` + `GOTO`. ~0,5.
- **S3** — переменные, `LET`, `IF/THEN`, `FOR/NEXT`, `INPUT`, `GOSUB`. ~1.
- **S4** — массивы/`DIM`, строки, `PEEK/POKE`, `BEEP`, ошибки, полировка. ~1.
